# Heavy, on-device ML stack for the audio super-resolution feature — kept
# SEPARATE from the fast-installing core requirements.txt on purpose. The API
# boots and `pnpm test:api` / `pnpm check:structure` pass WITHOUT this file
# installed, because everything here is lazy-imported inside
# app/repo/audiosr_engine.py only at the moment an enhancement job runs.
#
# Install it alongside the core requirements when you want to run the pipeline:
#   cd services/api && source .venv/bin/activate
#   pip install -r requirements.txt -r requirements-ml.txt
#
# The first enhancement run downloads the ~2 GB "basic" checkpoint once from the
# public HuggingFace hub (keyless), then caches it locally.
#
# Device note: CPU works for a short clip. The engine auto-detects CUDA → CPU at
# runtime (see repo/audiosr_engine.py select_device) and defaults to CPU. Apple
# MPS is skipped by default (AudioSR's latent-diffusion / torchlibrosa ops have
# known-unsupported MPS paths); opt in with AUDIOSR_DEVICE=mps. No GPU is ever
# required.

# --- torch stack, pinned DOWN to the last pre-torchcodec window ---------------
# audiosr 0.0.7 declares only FLOORS for the torch stack (torch>=1.13.0,
# torchaudio>=0.13.0, torchvision>=0.14.0), so a clean install pulls the LATEST
# torch. That is a false-green trap (same class as the matplotlib one below):
# modern torchaudio routes `torchaudio.load()` through `load_with_torchcodec`,
# which HARD-REQUIRES the undeclared `torchcodec` package (itself needing system
# FFmpeg libs). audiosr reads its input with `torchaudio.load` (see
# audiosr/utilities/data/dataset.py), so the marquee super-resolution op crashes
# at the audio-load step with "TorchCodec is required for load_with_torchcodec".
# audiosr 0.0.7 predates torchcodec and expects the classic soundfile/libsndfile
# load backend, so we pin the whole torch stack DOWN to the last window that
# still satisfies audiosr AND loads audio via soundfile (no torchcodec, no
# system-FFmpeg dependency). Keep the three in lockstep — torchaudio/torchvision
# wheels pin an exact matching torch build.
torch>=2.2,<2.3
torchaudio>=2.2,<2.3
torchvision>=0.17,<0.18

# versatile_audio_super_resolution — the marquee model. Its own dependency pins
# also fix transformers==4.30.2, librosa==0.9.2 and numpy<=1.23.5.
audiosr==0.0.7
# Writing the 48 kHz 16-bit PCM WAV rendition. (Also pulled by audiosr; pinned
# here because repo/audiosr_engine.py imports it directly.)
soundfile>=0.12.1
# Undeclared transitive dep of audiosr 0.0.7 — imported at module top-level in
# audiosr/utilities/tools.py (and latent_encoder/autoencoder.py, data/add_on.py)
# but MISSING from audiosr's own dependencies, so a clean install boots green yet
# the super-resolution op crashes with ModuleNotFoundError at runtime. Bounded to
# stay compatible with audiosr's numpy<=1.23.5 pin (matplotlib 3.8 pulls numpy up).
matplotlib>=3.6,<3.8
